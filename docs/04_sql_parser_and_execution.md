# 04. SQL処理系・型システム・実行エンジン

## 1. SQL パーサ & AST

### パーサの選定: `sqlparser-rs` の採用と拡張
- Java版H2は36万行超の自前パーサ（`Parser.java`）を保持していますが、Rustエコシステムでは成熟した標準クレートである **`sqlparser-rs`** が広く使われています。
- `sqlparser-rs` はPostgreSQL方言をはじめとする主要SQL方言を網羅しており、拡張構文（Vector型、カスタムインデックス、H2固有の構文）をサポートする独自 `Dialect` を実装することで、車輪の再発明を避けつつ高機能化を実現します。

```rust
pub struct H2Dialect;

impl Dialect for H2Dialect {
    fn is_identifier_start(&self, ch: char) -> bool { ... }
    // VECTOR(dim), JSON, GENERATED ALWAYS AS 等のカスタムトークン解析
}
```

## 2. 厳格かつモダンな型システム (`h2-types`)

SQLiteの弱点である「動的型付けによるバグ温床」を排除し、厳格な静的型チェックとリッチなモダン型を提供します。

```rust
#[derive(Debug, Clone, PartialEq, Serialize, Deserialize)]
pub enum DataType {
    // プリミティブ型
    Boolean,
    TinyInt,           // i8
    SmallInt,          // i16
    Integer,           // i32
    BigInt,            // i64
    Float,             // f32
    Double,            // f64
    Decimal(u8, u8),   // rust_decimal による任意精度固定小数点 (precision, scale)

    // 文字列・バイナリ
    Char(usize),
    VarChar(Option<usize>),
    Binary(Option<usize>),
    Blob,

    // 日時型 (chrono 準拠)
    Date,
    Time,
    Timestamp,
    TimestampTz,       // タイムゾーン付きタイムスタンプ

    // モダン・拡張型
    Uuid,              // uuid クレート準拠 (128bit)
    Json,              // ネイティブJSON (JSONBバイナリフォーマット)
    Array(Box<DataType>), // 可変長配列
    Vector(usize),     // AI/LLM埋め込みベクトル (要素数 dim の f32 配列)
}
```

### 値の表現 (`Value`)
行内の各フィールドは `Value` 列挙型としてゼロコピーまたは軽量参照で扱われます。

## 3. カタログ & メタデータ管理

データベース内のすべてのオブジェクト（スキーマ、テーブル、列定義、制約、インデックス、シーケンス、ビュー）は、システムカタログテーブル（`INFORMATION_SCHEMA`）としてMVStore内部の専用マップに永続化されます。

- **Schema**: デフォルト `PUBLIC`、複数スキーマ対応。
- **Table**: 列一覧、データ型、NULL許容、デフォルト式、生成列（Generated Column: STORED / VIRTUAL）。
- **Constraints**:
  - `PRIMARY KEY`, `NOT NULL`, `UNIQUE`, `CHECK`, `FOREIGN KEY` (CASCADE, SET NULL 等)。
- **Sequence**: 自動採番（`BIGINT GENERATED BY DEFAULT AS IDENTITY` や `CREATE SEQUENCE`）。
- **Indexes**:
  - `BTreeIndex`: 主キー、一意キー、範囲スキャン用。
  - `HashIndex`: 完全一致検索用。
  - `VectorHnswIndex`: 高次元ベクトル（Cosine類似度, L2距離, 内積）の近似最近傍検索 (ANN)。
  - `FullTextIndex`: BM25ベースの全文検索インデックス。

## 4. クエリ実行エンジン (Planner & Executor)

### 処理パイプライン
1. **Binding / Analysis**:
   - ASTのテーブル名・列名をカタログと照合して解決。
   - 型推論、型の暗黙キャスト、制約チェック。
2. **Logical Plan Generation**:
   - `Scan`, `Filter`, `Project`, `Join`, `Aggregate`, `Sort`, `Limit` などの論理演算子ツリーを構築。
3. **Optimizer (論理・物理最適化)**:
   - 述語プッシュダウン（FilterをScan直下に押し込み）。
   - 不要な列の射影プッシュダウン（I/O削減）。
   - インデックス選択（利用可能なIndexScanのコスト比較）。
   - Join順序最適化（サイズベースのHashJoin vs IndexNestedLoopJoin）。
4. **Physical Execution**:
   - **Volcano Iterator (Pull型実行)**:
     - `open()`, `next() -> Option<RecordBatch>`, `close()` のインターフェース。
   - **ベクトル化実行 (Vectorized Execution)**:
     - 1行ずつ処理するのではなく、タプルをまとめたチャンク（例: 1024行のバッチ）単位でSIMDを効かせて評価。
     - CPUキャッシュ効率を最大化し、大規模集計クエリを爆速化。

```text
               ┌───────────────┐
               │ Sort / Limit  │
               └───────▲───────┘
                       │
               ┌───────┴───────┐
               │  Hash Join    │
               └───▲───────▲───┘
                   │       │
       ┌───────────┴───┐   └───────────────┐
       │ Filter/Project│   │ Index Scan    │
       └───────▲───────┘   └───────────────┘
               │
       ┌───────┴───────┐
       │ Table Scan    │
       └───────────────┘
```
