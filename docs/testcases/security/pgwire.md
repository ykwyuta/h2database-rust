# PGWire・通信テストケース

共通の準備と判定方法は [README](README.md) を参照。異常なフレームは、テストハーネスから生の `TcpStream` に送る。長さは PostgreSQL v3 の big endian 32 bit とし、通常メッセージの長さには型バイトを含めない。

## WIRE-01 SSLRequest と資格情報の秘匿（P0）

- 手順: SSLRequest（長さ `00 00 00 08`、コード `04 D2 16 2F`）を送り、返答を記録する。パスワード付きユーザーの認証がネットワーク上で平文のまま可能かを確認する。
- 合格基準: ネットワーク利用の安全設定では TLS が成立するか、TLS 不可なら接続を拒否する。パスワードが平文でネットワークへ流れない。

## WIRE-02 StartupMessage の不正長・巨大長（P0）

- 手順: 最初の 4 バイトを `0`、`4`、`7`、`0x7fffffff`、`0xffffffff` に変え、後続は最小限だけ送る。各入力の後に接続を閉じる。
- 合格基準: 不正長は限られたメモリと時間で拒否される。巨大な確保、panic、プロセス終了がなく、次の正常接続が利用できる。

## WIRE-03 認証メッセージ・Query・CopyData の不正長（P0）

- 手順: 認証の `p`、認証後の `Q`、`COPY FROM STDIN` 中の `d` に対し、長さ `0`、`3`、`0xffffffff`、申告長より短い実データを送る。
- 合格基準: 各経路で有限の資源消費のうちに拒否または切断される。サーバーは生存し、DB の内容は変わらない。

## WIRE-04 途中切断時のトランザクション破棄（P0）

- 手順: `BEGIN`、`UPDATE public_data SET value='uncommitted' WHERE id=1` の後、`COMMIT` を送らずにソケットを閉じる。再接続して行を読む。
- 合格基準: 未コミット変更は見えず、再起動後も残らない。行ロックは解放される。

## WIRE-05 Simple Query の複数文と権限（P0）

- 手順: `reader` の `Q` メッセージで `SELECT * FROM public_data; UPDATE secret_data SET value='changed' WHERE id=1;` と、その順序を逆にした SQL を送る。
- 合格基準: 各文が個別に権限検証され、どちらの順序でも `secret_data` は変わらない。エラー後のトランザクション状態が一貫する。

## WIRE-06 認証前の接続放置と接続数（P1）

- 手順: StartupMessage を途中まで送って停止する接続を 100 本、認証直前で停止する接続を 100 本作る。同時に正常接続で `SELECT 1` を繰り返す。
- 合格基準: 認証前の読み取り期限・同時接続上限により資源使用量が制限され、正常クライアントが継続利用できる。

## WIRE-07 不正 UTF-8 と NUL の扱い（P1）

- 手順: StartupMessage の `user` 値と `Q` ペイロードに不正 UTF-8、途中の NUL、末尾 NUL 欠落を入れる。
- 合格基準: 不正入力を曖昧な別ユーザー名や別 SQL に置き換えて実行しない。安全に拒否し、プロセスは生存する。
