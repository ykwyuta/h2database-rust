# バックアップ・復旧（BKP）

共通のデータ、計測、判定は [README](README.md) を参照。

## BKP-01 静止時の完全復元（P0）

- 手順: `BACKUP TO '<temp>/base.json'` を実行する。別の新規 DB へ `RESTORE FROM '<temp>/base.json'` し、表、行、二次インデックス、シーケンスを照合する。`SCRIPT TO` / `RUNSCRIPT FROM` も別 DB で確認する。
- 合格基準: 元 DB と同じ論理データ・スキーマ・検索結果を得る。復元後の更新と再起動が成功する。形式と取得時点を識別できる。

## BKP-02 更新中の一貫したバックアップ（P0）

- 手順: 別セッションで `ops_data` と `ops_small` の対応する行を**同一トランザクション**で更新し続けながら、10 回バックアップを取る。各バックアップを別 DB に復元する。
- 合格基準: 各復元結果は単一のコミット境界に一致する。表間で片方だけ新しい状態や未コミット値を含まない。バックアップ中の書き込み停止時間を記録する。

## BKP-03 WAL と復旧時点（P0）

- 手順: 完全バックアップ後に A、B、C の識別可能なコミットを行う。A の後、B の後、C の後を目標に、それぞれ別 DB へ復旧する。時刻指定またはコミット番号指定のどちらかを利用できる運用インターフェースで行う。
- 合格基準: 指定した境界までのコミットだけが存在する。目標外の変更を混入させず、復旧可能範囲と必要な WAL を事前に確認できる。

## BKP-04 バックアップ検証と破損時の安全性（P0）

- 手順: 正常ファイル、途中で切ったファイル、1 バイト改変したファイル、別バージョン形式のファイルを検証する。既存データが入った復元先へ不正ファイルを指定する。
- 合格基準: 復元前に検証結果と理由を取得できる。失敗時は復元先が変更されない。成功後も新規 DB で全表検査できる。

## BKP-05 既存 DB への復元の置換意味（P0）

- 手順: バックアップ後に復元先だけに `extra_table` と追加行を作る。その DB に旧バックアップを復元して再起動する。
- 合格基準: 「全体置換」か「マージ」かの意味が明示され、全体置換なら追加表・行は残らない。途中失敗しても混合状態を成功として返さない。

## BKP-06 所要時間・容量・アクセス権（P1）

- 手順: 1 万行と 100 万行の DB でバックアップと復元の時間、出力サイズ、書き込み遅延を測る。読み取り専用ユーザーから実行し、保存先が書けない場合も試す。
- 合格基準: 容量見積もりと進捗・失敗理由が取得できる。権限のない操作は拒否され、部分ファイルを有効なバックアップと誤認しない。RPO/RTO は利用者が設定した目標と比較して記録する。
