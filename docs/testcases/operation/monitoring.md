# 監視・診断（MON）

共通のデータ、計測、判定は [README](README.md) を参照。

## MON-01 クエリ別統計の正確さ（P0）

- 手順: `RESET QUERY STATS` 後、数値・文字列リテラルだけ異なる同形 `SELECT`、成功・失敗する `UPDATE`、明示的 `COMMIT` を既知回数実行して `SHOW QUERY STATS` を読む。
- 合格基準: 正規化後の呼び出し数、エラー数、結果行数、時間・待機・WAL 指標の意味が一致する。統計取得自体が対象へ混入せず、リセット後は新しい期間として判別できる。

## MON-02 稼働中の待機とブロッカー（P0）

- 手順: セッション A が `ops_data.id=1` を更新して未コミットのまま保持する。B が同じ行を更新して待機し、C から稼働中の要求を調べる。
- 合格基準: B の経過時間、待機種別、待機対象、ブロッカー A、SQL または安全な識別子が分かる。A のコミット後に待機終了が観測できる。

## MON-03 クエリ実測とプランの対応（P0）

- 手順: 索引あり・なしで `EXPLAIN` と `EXPLAIN ANALYZE SELECT ... WHERE grp=1` を比較する。`UPDATE` 版は明示トランザクション内で実行して `ROLLBACK` する。
- 合格基準: 表示した計画が実際のアクセス経路と一致し、推定行数と実行行数、ノード別時間・I/O・待機の差を調べられる。更新文の実行有無が明確である。

## MON-04 再起動をまたぐ履歴と計画変化（P1）

- 手順: 同じ SQL を実行して統計と計画を記録し、DB を再起動する。その後に再実行し、期間別の性能・計画を比較する。
- 合格基準: 保存履歴、外部エクスポート、または明示的な永続ログによって、再起動前後を同一クエリとして比較できる。保持期間と上限が設定できる。

## MON-05 保守・バックアップ・WAL の状態（P1）

- 手順: 長めの `ANALYZE`、`VACUUM`、バックアップを開始し、別セッションから進捗、直近成功・失敗、所要時間、WAL サイズ、次のチェックポイント条件を取得する。I/O エラーも注入する。
- 合格基準: 作業の進行/停止と失敗を機械可読に判別できる。閾値超過や継続失敗を監視システムへ通知できる。

## MON-06 監視権限と負荷（P1）

- 手順: 管理者と一般ユーザーで統計・セッション・診断情報を取得する。高頻度の監視を有効/無効にして通常更新の TPS と p99 を比較する。
- 合格基準: 他ユーザーの秘密や管理指標を権限なく読めない。監視の CPU/メモリ/遅延への影響と保持上限を測定・制御できる。
