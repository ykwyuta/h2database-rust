# 実行計画の手動制御（PLAN）

共通のデータ、計測、判定は [README](README.md) を参照。`SET execution_mode` は行/Arrow 実行方式の切り替えであり、索引・結合順序の固定と区別する。

## PLAN-01 EXPLAIN と実際の経路（P0）

- 手順: `ops_data.grp` の索引を追加/削除し、`WHERE grp=0` と `WHERE grp=10` で `EXPLAIN`、`EXPLAIN ANALYZE`、実行時の `point_gets` / `scan_entries` を採る。
- 合格基準: EXPLAIN の走査種別・結合方式・行数が実際の実行経路を反映する。異なる場合は推定計画と実行計画の区別を表示する。

## PLAN-02 セッション限定の方式指定（P1）

- 手順: セッション A で `SET execution_mode='row'`、B で `'vectorized'` を設定し、同時に同じ集約を実行する。A だけ `'auto'` に戻す。
- 合格基準: 設定が意図したスコープだけに作用し、各セッションの結果は同一。再接続後の既定値、無効値の拒否、メモリ使用量を確認できる。

## PLAN-03 特定 SQL の走査・結合方式の誘導（P1）

- 手順: 大小表の結合と選択率の高低が異なるクエリに、サポートされるヒントまたはセッション設定で索引/全走査と結合順序を指定する。指定なしと結果・時間を比べる。
- 合格基準: 指定が計画と実行に反映され、結果は同一。指定できない場合は明示的エラーで知らせ、黙って無視しない。

## PLAN-04 良好計画の固定・解除（P1）

- 手順: 同じ SQL に対して統計更新前後の計画・実測値を採る。速い計画を管理者が固定し、再起動後の再利用と明示解除を確認する。
- 合格基準: 固定対象、適用回数、失敗理由、解除操作を確認できる。解除後は通常の最適化に戻る。

## PLAN-05 固定計画の無効化と安全な代替（P0）

- 手順: 索引に依存する計画を固定した後、その索引を削除・改名する。対象 SQL を実行する。
- 合格基準: 実行失敗または妥当な代替計画への切り替えを明示し、誤った結果を返さない。監視で固定失敗を検出できる。

## PLAN-06 権限・競合・変更履歴（P1）

- 手順: 一般ユーザーで計画固定を試し、管理者が同じクエリの固定・解除を複数セッションから更新する。
- 合格基準: 操作は適切な権限と監査記録を持つ。競合時の勝者と適用時点を判断できる。
