# 自動最適化（AUTO）

共通のデータ、計測、判定は [README](README.md) を参照。計画改善を確認するときは結果行と p95/p99 も比較し、EXPLAIN の文字列変化だけで合格にしない。

## AUTO-01 手動 ANALYZE の統計と永続性（P0）

- 手順: `ANALYZE ops_data` 前後の推定行数・コストを記録し、偏った `grp` の実測行数と比べる。再起動後も同じ推定情報が使われるか確認する。
- 合格基準: 行数・分布・最終更新時刻が確認でき、再起動後も有効。推定値が実データと著しく離れる場合は誤差を計測できる。

## AUTO-02 大量変更後の自動統計更新（P0）

- 手順: `ANALYZE` 後、`grp` の分布が逆転するほど更新・削除・追加する。手動 `ANALYZE` を実行せずに一定時間/クエリ回数待ち、統計時刻・推定行数・計画を記録する。
- 合格基準: 変更量に応じて統計が自動更新され、更新成功・失敗・次回予定を監視できる。通常クエリの結果は正しい。

## AUTO-03 選択率に応じた計画選択（P0）

- 手順: `grp=0`（多数行）と `grp=10`（少数行）を `ANALYZE` 後に実行し、索引/全走査の候補コスト・採用計画・実測 I/O を比較する。
- 合格基準: 複数候補を比較し、実測で大きな退行がない計画を選ぶ。誤推定時に原因と統計の更新方法が分かる。

## AUTO-04 結合順序と方式の自動選択（P1）

- 手順: 大表と小表、選択率の異なる 3 表を結合し、SQL の表記順とデータ分布を変えて `EXPLAIN ANALYZE` を取る。
- 合格基準: コストと行数に基づく順序・結合方式の選択が分かり、入力順だけで大きく退行しない。結果は全条件で同一。

## AUTO-05 計画回帰の検出と回復（P1）

- 手順: 初期計画の p95/CPU/I/O を基準にし、統計更新・索引変更で遅い計画を発生させる。複数回実行して検出、推奨、以前の良好計画への復帰、誤判定時の解除を確認する。
- 合格基準: 回帰と変更原因を履歴から追跡できる。自動制御を有効化した場合は改善を検証し、悪化したら解除する。

## AUTO-06 統計収集の負荷と安全性（P1）

- 手順: 100 万行・高カーディナリティ列で `ANALYZE` と自動収集を実行し、ピークメモリ、時間、通常更新の p99、キャンセル後の状態を測る。
- 合格基準: 資源上限・頻度・対象表を制御でき、業務処理を長時間止めない。失敗・キャンセル時に既存の有効統計を壊さない。
