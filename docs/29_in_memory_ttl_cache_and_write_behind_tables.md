# 29. インメモリTTLキャッシュテーブルおよび非同期Write-Behind機構の設計方針

> 作成日: 2026-09-26
> 関連要件: インメモリWALレス/低負荷テーブル、行単位TTLと有効期限延長、一定間隔での差分Write-Back（Write-Behind）、リードレプリカ同期両立
> 参照コード: `crates/h2-sql/src/{catalog.rs, executor/}`, `crates/h2-mvstore/src/{tx/, store.rs}`

---

## 1. 背景と設計目標

高頻度アクセスや一時的なデータ保持（Webセッション、リアルタイム集計、APIアクセスレート制限、一時的ステージング）において、Redis等の外部インメモリKVSとRDBを併用するシステム構成が広く普及しています。
しかし、外部キャッシュとRDBの二重管理には以下の重大な課題が存在します：

1. **整合性の乖離とキャッシュ無効化の複雑性**: アプリケーション側でDual-Writeを行うと、障害時の不整合やキャッシュ破棄漏れが発生しやすい。
2. **インフラ運用の肥大化**: キャッシュサーバーとRDBの双方でクラスタ管理、障害監視、フェイルオーバー設計が必要となる。
3. **トランザクション境界の分断**: 外部キャッシュへの操作はRDBのACIDトランザクションと結合できず、ロールバック時にキャッシュのみ残留する。

本設計では、**「オンメモリの一時キャッシュ」と「永続化テーブルへの非同期Write-Back（Write-Behind）」をRDB内部で完結**させ、外部KVSを不要とする高スループット・低レイテンシなインメモリテーブル基盤を提供することを目標とします。
また、リードレプリカへの変更同期の実現と、ディスクI/O負荷の極小化を両立させます。

## 3. DDL構文およびテーブルオプション仕様

### 3.1 DDL構文

キャッシュテーブルは専用構文 `CREATE CACHE TABLE` または `WITH (TYPE = 'CACHE', ...)` で定義します：

```sql
CREATE CACHE TABLE user_sessions (
    session_id VARCHAR(64) PRIMARY KEY,
    user_id BIGINT,
    payload TEXT
) WITH (
    TTL = '30m',                       -- 行単位のデフォルト有効期限 (30分)
    WRITE_BACK_TABLE = 'user_sessions_backup', -- ディスク永続化先テーブル名
    WRITE_BACK_INTERVAL = '5s',        -- 差分永続化インターバル (5秒間隔)
    WRITE_BACK_MODE = 'BOTH',          -- 'UPSERT' (差分反映), 'DELETE' (失効時削除), 'BOTH'
    UNLOGGED = TRUE                    -- コミットごとの同期fsyncを抑制
);
```

### 3.2 テーブルオプション一覧

| オプション名 | 型 | デフォルト値 | 説明 |
| :--- | :--- | :--- | :--- |
| `TTL` | 時間文字列 / ms | なし (無期限) | INSERT 時に `_expires_at` 未指定の場合のデフォルト有効期間（例: `'10s'`, `'1h'`, `'7d'`） |
| `WRITE_BACK_TABLE` | 文字列 | なし | 差分を書き戻す永続化先テーブル名（同一主キー構成を持つテーブル） |
| `WRITE_BACK_INTERVAL` | 時間文字列 / ms | `'1s'` | バックグラウンドで差分書き戻しを実行するインターバル |
| `WRITE_BACK_MODE` | 文字列 | `'UPSERT'` | `'UPSERT'` (変更行の書き戻しのみ), `'DELETE'` (失効行の永続化先削除), `'BOTH'` (両方) |
| `UNLOGGED` | 真偽値 | `TRUE` | キャッシュテーブル単体トランザクションでの即時 `fsync` を省略し低I/O化 |

## 4. 行単位TTLと暗黙のシステム疑似列

### 4.1 疑似列の構造
キャッシュテーブルを作成すると、以下の列が自動的に先頭に定義されます：
- `_expires_at` (`DataType::BigInt`): UNIX エポックミリ秒。有効期限の終了時刻。
- `_created_at` (`DataType::BigInt`): UNIX エポックミリ秒。行の生成/最終更新時刻。
- `_dirty` (`DataType::Boolean`): 直近の Write-Back 以降に変更されたかを示すフラグ。

### 4.2 能動的 TTL フィルタリング (Active TTL Filtering)
`SELECT`, `UPDATE`, `DELETE` クエリを実行する際、キャッシュテーブルに対して暗黙のフィルタ `_expires_at > CURRENT_TIME_MILLIS()` が適用されます。
これにより、アプリケーション層は期限切れ行の存在を意識することなく、透過的に有効なキャッシュのみを取得できます。

### 4.3 有効期限の期間延長 (TOUCH)
有効期限の延長は以下の2通りの方法で実行できます：

1. **専用ステートメント**:
   ```sql
   TOUCH user_sessions WHERE session_id = 'sess_123' EXTEND '30m';
   ```
   `EXTEND` を省略した場合はテーブルのデフォルト `TTL` が加算されます。
2. **標準SQL**:
   ```sql
   UPDATE user_sessions SET _expires_at = _expires_at + 1800000 WHERE session_id = 'sess_123';
   ```

## 5. 非同期 Write-Back (Write-Behind) 機構

### 5.1 差分抽出とバッキングテーブル同期
`_dirty = true` の行のみが Write-Back の対象となります。

1. **差分スキャン**: `cache_tbl` を走査し、`_dirty = true` かつ有効な行を抽出。
2. **バッキングテーブルへの UPSERT**:
   - 永続化テーブル（`WRITE_BACK_TABLE`）に対し、主キー一致による更新または新規挿入（`MERGE INTO` / `INSERT ON CONFLICT DO UPDATE` 相当の処理）を実行。
3. **フラグのリセット**: キャッシュテーブル内の対象行の `_dirty` を `false` に更新。
4. **失効行の削除同期**:
   - `WRITE_BACK_MODE` が `'DELETE'` または `'BOTH'` の場合、期限切れとなった行を永続化テーブルからも `DELETE`。
   - キャッシュテーブルから当該期限切れ行を物理削除。

### 5.2 即時フラッシュ・パージコマンド
バックグラウンド定期実行のほか、保守や即時反映用のSQLコマンドを提供：
- `FLUSH WRITE_BACK <table_name>;` : 未反映の差分を今すぐ永続化テーブルへ書き戻す。
- `PURGE EXPIRED FROM <table_name>;` : 期限切れ行を即座に回収する。

## 6. I/O負荷低減とレプリケーション両立

1. **WAL 同期抑制による低負荷化**:
   - 通常テーブルではコミット時に `wal_manager.sync()` (fsync) が発行されますが、`UNLOGGED = TRUE` のキャッシュテーブルに対する更新では即時 fsync をバイパスします。
   - メモリ上のバージョン管理ツリー（MVStore）のみを高速更新するため、ディスクI/Oボトルネックが発生しません。
2. **リードレプリカ同期**:
   - WAL レコード自体はメモリバッファ上にシーケンシャルに生成・保持されるため、レプリケーション接続（`h2::replication`）のログシッピング機構にはそのまま軽量ストリームとして供給可能です。
   - レプリカ側でも同一のインメモリキャッシュ状態が維持されます。
3. **耐久性確保の境界**:
   - 一時キャッシュが万が一クラッシュした場合でも、Write-Behind によってディスクに書き戻されたデータは永続化テーブル側に保護され、起動時に必要に応じてバッキングテーブルからキャッシュを再加温（Cache Warming）できます。

## 7. 実装およびテスト計画

1. **カタログ層の拡張 (`catalog.rs`)**:
   - `TableDef` に `is_cache`, `cache_ttl_ms`, `write_back_table`, `write_back_interval_ms`, `write_back_mode`, `is_unlogged` フィールドを追加。
   - `TableDef::new_cache` コンストラクタを実装。
2. **構文解析およびステートメント実行 (`executor/statement.rs`, `executor/admin.rs`)**:
   - `CREATE CACHE TABLE ... WITH (...)` の解析・生成。
   - `TOUCH ... WHERE ... [EXTEND ...]` ステートメントの実装。
   - `FLUSH WRITE_BACK ...` および `PURGE EXPIRED ...` の実装。
3. **クエリ実行層の TTL フィルタリング (`executor/query.rs`)**:
   - キャッシュテーブル走査時に `_expires_at <= now` のタプルを自動スキップ。
4. **結合テストの作成 (`crates/h2/tests/cache_table_write_behind_tests.rs`)**:
   - キャッシュテーブルの作成・システム疑似列の確認
   - TTL 自然失効とクエリからの透過的不可視化
   - `TOUCH` コマンドによる有効期限延長
   - 変更行のみの差分 Write-Back (UPSERT)
   - `WRITE_BACK_MODE = 'BOTH'` による失効行の削除伝播
   - `PURGE EXPIRED` によるメモリ回収
