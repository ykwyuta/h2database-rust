# demo/008: AWS Aurora 型 コンピュート・ストレージ完全分離クラスタ

本デモは、AWS Aurora や Google Cloud AlloyDB が提唱する **「コンピュート・ストレージ完全分離（Decoupled Storage-Compute）」** および **「ログそのものがデータベースである（The Log is the Database）」** アーキテクチャを実演します。

---

## 🌟 実演内容

1. **4 of 6 Quorum (3 AZ 分散スマートストレージフリート)**:
   - 3つのアベイラビリティゾーン（AZ-1, AZ-2, AZ-3）に各2ノード、計6ノードのスマートストレージノードを配置
   - 書き込みクォーラム: 4 of 6、読み取りクォーラム: 3 of 6
2. **"The Log is the Database" (ログのみ転送)**:
   - 8KB/16KB のダーティデータページ転送を完全撤廃し、軽量な WAL ログレコードのみをクォーラム並行送信
   - 各ストレージノードはログを高速にアペンドし、即時 ACK を返却（Tail Latency の解消）
3. **共有ストレージ・ゼロストレージ・リードレプリカ**:
   - リードレプリカは専用ストレージを持たず、同一のストレージフリートを共有（追加ストレージコスト 0）
   - キャッシュミス時に共有ストレージ層からオンデマンドでページ/キーを取得
4. **耐障害性と無停止稼働**:
   - AZ-1 の 2 ノードが完全停止（1 AZ 完全喪失）しても、残り 4 ノードで書き込みクォーラムが成立し、サービスを無停止継続
5. **ピアツーピア・ゴシップ自己修復 (Peer Gossip Self-Healing)**:
   - 復旧したノードが健全なピアノードと LSN 範囲を照合し、欠落ログを自動同期して追いつく
6. **瞬間フェイルオーバーとスプリットブレイン防止**:
   - リードレプリカを新世代 `FencingToken` で新 Primary に即座に昇格（ストレージ層がマテリアライズ済みのため、クラッシュリカバリ走査不要）
   - 旧 Primary からの遅延パケットはストレージ層の Fencing Token チェックで自動的に弾かれ、スプリットブレインを確実に防止

---

## 🏃 実行方法

```bash
cargo run -p demo-decoupled-aurora
```
